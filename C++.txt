** #include <iostream>
** #include <string>
** using namespace std;

** int main(){
**      string food  = "Pizza";      -----> creates a memory space with 'Pizza' and that value is referenced with 'food'
**      string &meal = food;         -----> Here if u use 'meal = "Pizza"', it would have created a new memory space with "Pizza" again.
**      cout << food << "\n";               by using '&meal = food', we are saying meal = diff,. name for "Pizza" mem location.
**      cout << meal << "\n";               saving memory.
**      cout << &meal << "\n";

**      cout << "-------------------------\n";
**      meal = "Burger";             -----> If we change 'meal = "Burger"' or 'food = "Burger"', both the food and meal values change.
**      cout << food << "\n";
**      cout << meal << "\n";
**      cout << &meal << "\n";
**      return 0;

CAPTURE BY REFERENCE : If you want the lambda to use the latest value of a variable(not just a copy), you can use "[&]" to capture it by
reference. This means the lambda will work the original variable, not a seperate copy:
** #include <iostream>
** using namespace std;

** int main() {
**      int x = 10;
**      auto show = [&x](){
**          cout << x;
**          x = x+1;
**      };
**      x = 20;
**      show();             --> Prints 20
**      cout << x << endl;  --> Prints 21
**      return 0;
** }

# Rules of "using Base::Base;" shortcut : 
  Rule:
    Inherits constructors visible at that scope 
    Detail : Private Base constructor are not inherited.

  Rule:
    Members of the derived class get default-intialized.
    Detail : Any Inherited constructor only sees the base's parameters; derived members rely on in-class initializers.

  Rule:
    Does not inherit copy/move constructors.
    Detail : These are execluded; the compiler generates them for the derived class as usual.

  Rule:
    You can still write your own constructors for derived class.
    They coexist with the inherited ones, the overload resoution picks the best match.

# "using Base::Base;" fits when the derived class is mostly a wrapper or a marker type that doesn't carry new mandatory state.
  If your derived has its own non-defaultable fields, write explicit constructors that intialize them properly instead of 
  relying on inheritance.

## The "constexpr" specifier :
## The "constexpr" specifier in C++ indicates that a value or function can be evaluated at compile time. It allows the compiler to
## .. perform optimization and ensures that certain expressions are evaluated at compile time, improving performance.
## In the context of templates, "if constexpr" is particularly useful. It enables compile-time branching meaning the condition is 
## evaluted at compile time, and only the relevant branch is compiled. here's an example.

** #include <iostream>
** #include <type_traits>

** struct Wrapper {
**      int value;
** };

** Wrapper wrap(int x) {
**      return {x*2};
** }

** int increment(int x) {
**      return x+1;
** }

** template <typename T, typename Func>
** auto apply(T value, Func func) {
*       auto result = func(value);
**      if constexpr (std::is_same_v<decltype(result), Wrapper>) {
**          return result.value;
**      }
**      else {
**          return result;
**      }
** }

** int main() {
**      int x = 5;

**      auto wrappedResult = apply(x, wrap);
**      std::cout << "Wrapped Result: " << wrappedResult << '\n';

**      auto incrementResult = apply(x, increment);
**      std::cout << "Incremented Result: " << incrementResult << "\n";

**      return 0;
** }

## In the apply function, if constexpr is used to decide at compile-time which branch of code should be executed based on the type of ..
## ..result. When result is of type Wrapper, the function unwraps its value; otherwise, it returns the result directly. This approach ..
## ..provides type safety and avoids runtime type checks, making your code more efficient.
## By using constexpr for compile-time decisions, you can make your template functions more flexible and efficient, avoiding ...
## ...unnecessary 
## overhead. This will come especially useful in the last lesson of this course.
